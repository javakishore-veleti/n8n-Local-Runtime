⚡ AI-POWERED TEST VALIDATION PLATFORM
SkillForge
Empower business users to validate end-to-end digital sales services in plain English — no coding, no API knowledge, no waiting on engineering.
VISION
A world where any business user can validate any test scenario across any combination of integrated enterprise systems — by simply describing what they want to verify in their own words. The platform translates business intent into API orchestration, making integration testing as easy as asking a question.
OBJECTIVE
Build a Skills-based platform where QA engineers encode test knowledge into reusable SKILL.md files, and business users execute them on-demand with dynamic criteria. Replace manual, engineering-dependent testing with self-service AI-powered validation — reducing test cycle time by 10x while expanding coverage.
THE PROBLEM
🐌
Manual & Slow
Business users rely on QA engineers to run every test scenario manually using Postman, scripts, or direct API calls. Testing becomes the bottleneck for every release.
🧠
Trillion Combinations
Every business user has a different need — testing products, pricing, tax, channels, markets, vehicle configurations. No fixed test suite can cover infinite variation.
🔒
Knowledge Silos
API endpoints, authentication flows, data models, and assertion logic live in individual engineers' heads — not in reusable, shareable artifacts.
🚫
No Self-Service
Business users cannot independently validate any scenario without developer assistance. They wait in queue while time-sensitive testing doesn't get done.
THE SOLUTION — THREE SIMPLE CONCEPTS
📝
Skills
QA engineers encode test scenarios once into reusable SKILL.md files. Each skill is a recipe — describing the workflow, inputs, APIs, and assertions in structured natural language.
🤖
Smart Execution
AI reads the skill, authenticates with each system, orchestrates API calls in the right order, passes data between steps, and evaluates results — all automatically.
📊
Business Results
Results in plain English: "4 of 4 channels returned valid offers. Orders created. Tax matched expected rates." Failures include clear explanations — no raw API output.
KEY PRINCIPLES
1
SKILL.md is the contract — A single file serves as documentation, executable instructions, and the bridge between business intent and API orchestration.
2
Author once, execute infinitely — QA engineers encode knowledge once. Business users run skills with different inputs endlessly — no re-authoring needed.
3
Credentials never exposed — The Service Registry manages all API auth centrally. Skills reference services by name. Users never see tokens, endpoints, or secrets.
4
95/5 execution model — AI handles 95% of skills dynamically. The 5% that need 100% determinism get hardened as Temporal workflows — same SKILL.md, guaranteed execution.

SKILL.md Anatomy
The internal structure of a SKILL.md file — the single source of truth that bridges business intent and API execution.
METADATA (YAML Front Matter)
name Skill name
version Semantic version
author Creator
tags Searchable labels
execution_mode ai or workflow
description Purpose and scope
UICriteria
<Type> HTML / Excel / Both

HTML Mode: Field definitions with label, type (select, multi-select, text, checkbox), options, defaults, required flag

Excel Mode: Expected columns, types, downloadable template
WorkflowDefinition — Tasks
Task 1: Create Vehicle
Service: TDI
Inputs: {model_year}, {make}, {country}
Capture: account_number, vin
Assert: values not null
Task 2: Onboard
Service: DSS
Inputs: {Task1.account_number}, {Task1.vin}
Capture: enrollment_status
Assert: status = ACTIVE
Task 3: Get Offers
Service: OffersAPI
Loop: for each channel
Capture: offers[], offer_ids[]
Assert: offers not empty
Task 4: Create Quote
Service: OrdersAPI
Loop: for each offer
Capture: quote_id, tax_details
Conditional asserts on tax/pricing
Task 5: Create Order
Service: OrdersAPI
Loop: for each quote
Capture: order_id, order_status
Assert: status = CREATED
Task 6: Verify
Service: OrdersAPI
Operation: getOrders
Assert: order count matches
Optional: EventHub listen
OutputDefinition (Optional)
Natural language description of desired report format: summary table, channel breakdown, tax details, pricing comparison, pass/fail per step.
Scripts (Optional)
Supporting scripts for complex logic:
eventhub_listener.py → Task 6
tax_validator.sh → Task 4
Executed in sandboxed Docker containers.

Dual Execution Model
Same SKILL.md, two execution paths — AI-powered for flexibility, Temporal workflows for deterministic reliability.
~95%
AI-Interpreted Execution
The AI reads the SKILL.md at runtime, interprets the workflow dynamically, and orchestrates API calls. Default path for all skills. No developer needed after skill authoring.
Fast to create — author SKILL.md and go
Flexible — handles variations gracefully
AI interprets natural language assertions
Cost: AI tokens per execution
Best for: ad-hoc testing, new scenarios, exploration
OR
~5%
Hardened Workflow Execution
A developer implements the same SKILL.md as a Temporal workflow. 100% deterministic, repeatable, and reliable. Same inputs and outputs — user sees no difference.
Requires developer implementation
Deterministic — same input, same execution
Built-in retry, timeout, failure recovery
Java / Node.js / Go / Python SDK
Best for: release gates, compliance, regression
Lifecycle: Start with AI execution → Identify critical skills → Harden to Temporal as needed
